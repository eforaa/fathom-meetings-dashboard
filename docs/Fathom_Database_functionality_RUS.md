# Fathom Database — что умеет и чего не умеет

Описание по состоянию на **8 октября 2026**, составлено по коду, а не по памяти.
Всё, что здесь названо работающим, подтверждено тестами или проверкой на живой
базе; всё, что не сделано, названо не сделанным.

---

## 1. Что это такое

База всех рабочих встреч, записанных через Fathom. Забирает их по API, хранит
вместе с участниками, конспектом и транскриптом и показывает одной таблицей.
Работать с ней можно двумя руками:

- **сайт** — таблица: фильтры, сортировка, группировка, свои колонки, правка
  мышкой;
- **Claude через коннектор** — те же данные словами: «найди все встречи с
  клиентами», «назови безымянные», «проставь теги».

Технически: Next.js на Vercel, Postgres в Supabase, вход через Google,
MCP-коннектор для Claude. 885 проверок в 38 файлах тестов.

---

## 2. Как встречи попадают в базу

### Синхронизация по ключу

У каждого человека свой ключ Fathom, введённый на странице настроек. Ключ
шифруется (AES-GCM) и хранится зашифрованным; наружу показывается только
последние четыре символа.

Синхронизация забирает всё, что появилось с прошлого раза, и складывает под
того владельца, чей ключ. Одна и та же встреча у двух людей хранится двумя
строками — так задумано, у каждого своя разметка.

**Важное ограничение, которое не лечится кодом:** ключ показывает только то,
что записано или расшарено **ему**. Встречи, записанные другим аккаунтом,
синхронизация не увидит никогда.

### Первичная загрузка архива

Отдельный проход идёт вглубь постранично, сохраняя курсор после каждой
страницы, — поэтому его можно прерывать и продолжать. Когда страницы кончились,
аккаунт помечается завершённым.

### Расписание

| что | когда | где настроено |
|---|---|---|
| сбор встреч | ежедневно 17:00 UTC | `vercel.json` |
| резервная копия | ежедневно 03:00 UTC | `vercel.json` |

### Ручной импорт через Claude

Инструмент `import_meetings` принимает встречи, прочитанные **другим**
коннектором Fathom, и кладёт их в базу. Это единственный способ добавить
встречи чужого аккаунта. Уже загруженная встреча не задваивается — ей
дополняются конспект и список участников.

## 3. Названия встреч — как это работает на самом деле

Это главный вопрос, поэтому подробно.

### Четыре поля, а не одно

У встречи одновременно живут четыре названия:

| поле | откуда | можно ли трогать |
|---|---|---|
| `title` | оригинал из Fathom (имя из календаря) | **никогда** |
| `fathom_title` | строка «цель встречи», которую пишет сам Fathom | нет |
| `ai_title` | сгенерированное имя, показывается с меткой 🤖 | да |
| `custom_title` | имя, продиктованное человеком | да |

**Порядок показа:** ручное → настоящее календарное имя → 🤖-сгенерированное →
строка цели от Fathom → метка «нужно имя».

Настоящее календарное имя стоит **выше** сгенерированного намеренно: иначе
разбор молча переписывал бы встречи, у которых уже есть нормальное название.
Человек может закрепить любой источник для конкретной встречи — закрепление
ничего не удаляет.

### Что делается автоматически

Автонаименование есть, но покрывает оно **только один случай** — регулярные
встречи. Работает так:

1. Среди уже названных встреч владельца ищутся **серии** — название,
   повторяющееся **не менее трёх раз**.
2. Для каждой серии считается портрет: **ядро участников** (те, кто был не
   менее чем в половине встреч серии), **обычный час** по киевскому времени и
   медианная длительность.
3. Свежая безымянная встреча сравнивается с каждой серией: совпадение
   участников не ниже **0,6** (мера Жаккара) **и** час попадает в ±1 час от
   обычного.
4. При уверенном совпадении пишется `ai_title` с именем серии. Метка 🤖,
   откатывается одним кликом.

**Чего автомат НЕ делает — и это важно:**

- **Срабатывает только на новых встречах**, прямо в момент загрузки. Задним
  числом по базе не проходит. Безымянные встречи, уже лежащие в базе, он не
  тронет никогда.
- **Не работает для разовых встреч.** Если это не повторяющаяся серия,
  сопоставлять не с чем — встреча останется «без названия».
- **Не придумывает названия.** Он только переносит имя найденной серии. Никакой
  модели здесь нет, это чистое сопоставление.
- Не трогает настоящее календарное имя.

Что не совпало — остаётся «без названия» и попадает в фильтр «без назви» на
главной, чтобы человек увидел и поправил.

*Мелочь из кода:* медианная длительность серии считается, но в сравнении не
участвует — сопоставление идёт только по участникам и часу. Не ошибка, но поле
лежит мёртвым.

### Что делает Claude

Всё остальное — через коннектор, по скиллу `title-meetings`. Правило названия:

> **суть темы (3–5 слов, без глаголов) + инициалы 1–3 ключевых участников в
> скобках**

Суть берётся из **цели** встречи — первой строки конспекта Fathom, а не из
тем и не из транскрипта. Примеры:

- ✅ «Плагин Fathom — синхронизация данных (ПА, ОА, ВС)»
- ❌ «Согласовать разработку плагина» — глагол, это цель дословно
- ❌ «PM плагин — миграция БД» — это инструменты из транскрипта, а не цель

Без эмодзи в тексте (значок рисует интерфейс), один алфавит в заголовке,
инициалы в две буквы.

Пишется это в `ai_title` — то есть всегда откатывается, оригинал цел.

### Итог одной фразой

Автоматически называются **только повторяющиеся встречи и только в момент
загрузки**. Всё разовое и всё, что уже лежит в базе, называет Claude по
просьбе. Полностью автоматического переименования всей базы в системе нет и
никогда не было.

## 4. Что умеет сайт

**Таблица встреч** — дата, название, тип, важность, участники, состояние
разбора. Первая колонка примерзает при прокрутке, ширины тянутся мышью и
запоминаются, строки чередуются фоном, кликается вся строка.

**Отбор:** поиск по названиям и конспектам, фильтры по колонкам (И между
колонками, ИЛИ внутри одной), конструктор условий, диапазон дат с быстрыми
кнопками (живёт в адресе — ссылкой можно поделиться), фильтры «пробелов»: без
названия, без конспекта, без типа, без оценки.

**Группировка** до трёх уровней вложенности, уровни без значений
пропускаются.

**Правка:** название, конспект, важность звёздами, типы (до четырёх), свои
колонки — текст, число, список, мультисписок, галочка. Пакетная правка
выделенных строк.

**Группы встреч** (они же папки/теги) с вложенностью — отдельное дерево поверх
таблицы.

**Виды:** таблица или карточки, сохранённые виды в тулбаре, командная палитра
на ⌘K, корзина с восстановлением.

**Экспорт** текущего списка в CSV или Markdown — ровно то, что на экране, в том
же порядке.

**Страница «Люди»** — встречи по участникам, с объединением псевдонимов.

**Страница «Подключение»** — личная ссылка коннектора с кнопкой «скопировать».

**Интерфейс на трёх языках**, украинский по умолчанию, переключатель одной
кнопкой.

## 5. Что умеет Claude через коннектор

23 инструмента. Коннектор видит только встречи владельца токена.

**Читать:** `list_meetings` (фильтры по типу, датам, названию, участнику, плюс
`needs` — очередь «чего не хватает»), `get_meeting`, `get_transcript` (кусками),
`search_participants`, `get_stats`.

**Править:** `set_meeting_title`, `set_meeting_summary`,
`set_meeting_importance`, `set_meeting_types`, `set_meeting_field`,
`save_meeting_analysis`.

**Колонки:** `list_custom_columns`, `create_column`, `delete_column`.

**Группы:** `list_groups`, `create_group`, `rename_group`, `move_group`,
`delete_group`, `list_group_meetings`, `assign_meetings_to_group`,
`remove_meetings_from_group`.

**Добавить:** `import_meetings`.

Инструкция для подключающегося Claude встроена в сам коннектор — отдельный
скилл ставить не нужно. В ней записаны правила названий и предупреждение, что
один человек может быть записан под несколькими почтами, поэтому искать надо по
всем псевдонимам.

## 6. Разбор встреч

Скилл `analyze-meeting`: заполняет заголовок, конспект, темы и тип.

- Источник — **готовый конспект Fathom**, он короткий и точный. Транскрипт
  целиком читается, только если конспекта нет.
- Язык разный у разных полей, так уже лежит в базе: **заголовок на языке
  встречи**, **конспект и темы на английском**.
- Тип — ровно один из пяти: планёрка, встреча с клиентом, автоматизация,
  онбординг, прочее. При двуликости основной пишется в тип, оба — в набор типов.
- **Задачи не пишутся принципиально.** У Fathom есть свой список, второй рядом —
  два источника правды об одном и том же, и наш никто не ведёт. Поле всегда
  передаётся пустым, чтобы чистились и старые значения.
- Важность руками не ставится: это суждение человека, а не вывод из транскрипта.

Ночного автоматического разбора **нет**. Он был, упёрся в дневную квоту
бесплатной модели и остановился. Всё, что разобрано, разобрано вручную через
коннектор.

## 7. Надёжность

**Тесты:** 885 проверок в 38 файлах, идут за секунду, не требуют ни базы, ни
переменных окружения. Фреймворка нет намеренно.

Отдельный класс — **сторожевые тесты на тихие ошибки CSS**: каждая переменная
должна быть объявлена, полоса с прокруткой должна начинаться слева, ничто
плавающее не имеет права брать полупрозрачный фон. Каждый такой тест заведён
после настоящей поломки и проверен её возвратом.

**Проверки на входе:** потолок тела запроса 64 КБ, битый JSON отвечает 400,
кривой идентификатор ловится до базы.

**Лимиты:** правка 60/мин, ключ Fathom 10/мин, синхронизация 5 за 10 минут,
коннектор 120/мин, подбор секрета 20/мин. Честная оговорка в самом модуле:
счётчики живут в памяти одного экземпляра, а их несколько — это защита от
сорвавшегося скрипта, не от распределённого потока.

**Резервная копия** собирается еженощно, хранятся последние семь.
Восстановление **отрепетировано на живых данных**: строка была удалена и
возвращена из копии, поле в поле. Инструмент по умолчанию ничего не пишет —
сначала показывает, чем копия отличается от базы.

**Журнал синхронизаций** — чтобы молчание было видно.

## 8. Доступ

Два независимых механизма:

- **вход на сайт** — Google плюс список допущенных почт (`ALLOWED_EMAILS`);
- **коннектор** — личный токен прямо в адресе (`MCP_TOKENS`, пары
  `токен:почта`). OAuth не используется вообще.

Обе переменные живут **в Vercel** и подхватываются только при сборке: после
правки нужен новый деплой. Локальный файл `.env.local` на живой сайт не влияет
— их расхождение уже один раз стоило нам нескольких дней путаницы.

Токен решает, **чьи** встречи человек увидит. Ссылка = пароль: у кого она есть,
тот вошёл, без всякого Google.

## 9. Чего нет

### Просили или обсуждали, но не сделано

| что | состояние |
|---|---|
| Кадры с экрана встречи в разбор | обсуждали, не начинали. Видео через API Fathom не отдаётся вовсе — только страница записи, поэтому нужен браузер с живой сессией. На Vercel не живёт |
| Несколько ключей Fathom на одного человека | нет. Один адрес — один ключ, поэтому второй аккаунт нельзя подключить под собой |
| Фильтрация и сортировка в SQL | нет, идёт в Node. Замерено: 456 встреч — 1196 мс. На пяти тысячах страница перестанет открываться |
| Автоматический разбор по расписанию | нет и не планируется в прежнем виде |
| Поиск по словам внутри транскриптов | **убран 13.10.2026**: хранил каждую расшифровку трижды и переполнил базу. Транскрипты остались и читаются как раньше |
| Экран управления токенами | нет. Токены правятся только в панели Vercel |

### Висит на стороне человека

| что | кто |
|---|---|
| **Таблица `custom_columns` открыта на чтение и запись публичным ключом.** Проверено вручную ещё в августе: чужая строка читается и пишется. Лечится одной строкой `alter table custom_columns enable row level security` | Sofiia, консоль Supabase |
| У аккаунта `d.soloviov@aivocado.ai` нет ключа Fathom: 383 встречи не обновляются с 8 июня | ключ вводит сам человек |
| У этих же 383 встреч ноль конспектов Fathom при наличии транскриптов — дозаливается импортом | можно сделать сейчас |
| Один ключ Fathom подключён под двумя почтами: задвоенные встречи, лишние транскрипты, растёт ежедневно | решение чьё-то, не техническое |
| Почасовой сбор бьёт в чужой адрес | правка в одну строку |

### Чего не будет, потому что данных нет

Архив **за 2025 год и январь 2026** недоступен. Проверено прямыми запросами к
Fathom: один ключ не отдаёт ничего раньше 3 апреля 2026, другой — раньше
1 февраля 2026. Это не блокировка на нашей стороне и не ошибка загрузки: этих
записей нет в самом Fathom. Февраль и март 2026 при этом в базе есть.

## 10. Ловушки, на которых уже обожглись

- **Переменные Vercel подхватываются только при сборке.** Правка без деплоя не
  действует — ровно отсюда растут «ключ не работает» и «ничего не изменилось».
- **Замена значения `MCP_TOKENS` целиком убивает чужие живые токены.**
  Дописывать можно только в конец.
- **Оборванная ссылка коннектора** (без токена) раньше отдавала HTML-страницу с
  кодом 200, из-за чего Claude уходил в OAuth и выдавал «add an OAuth Client
  ID». Починено: теперь 400 и внятный текст. OAuth Client ID вписывать не надо
  никогда.
- **Старая запись коннектора перебивает новую.** Перед повторным подключением:
  `claude mcp remove fathom-meetings`.
- **Пустой список вместо ошибки.** Токен с почтой, под которой в базе нет
  встреч, подключается без единой ошибки и показывает пустоту. Выглядит как
  поломка, хотя всё исправно.
