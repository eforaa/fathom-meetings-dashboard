# Fathom Database — заметки в карту, 19.08.2026

Сгруппировано по смыслу, а не по времени: в карте живут темы, а не порядок,
в котором до них дошли руки. Числа — измеренные, не оценочные.

---

## 1. Данные говорят правду

### Один человек — одна запись

- Причина: Fathom описывает участника из двух источников — календарь знает
  адрес, расшифровка знает имя, и часто ни один не знает вторую половину
- Ключом участника было «почта, а если нет — имя», поэтому один человек
  заводился дважды
- Отдельно: у 52 записей адрес стоял **в поле имени** — для системы это было
  имя, и человек оставался разделён со своим же именем
- Было → стало: в 370 встречах из 1088 кто-то показан дважды → **0**;
  записей участников 5525 → 4508; строк в фильтре «Люди» 159 → 127
- Счётчики поехали в обе стороны: 760 → 567 у одного, 734 → **958** у другого
  (встречи, где он значился только рабочим адресом, теперь его)
- Механизм склейки уже был — для страницы «Люди»; главная таблица им не
  пользовалась
- Осталось: трое разделены до сих пор, связать автоматически нечем

### analysis_status: очереди не существует

- Поле осталось от ночного разбора, которого давно нет
- Сводка отдавала «в очереди: 1027» — читалось как тысяча ждущих обработки
- Договорились: пусто = разбор не запрашивали, `done` = сохранён,
  `failed` = не вышло
- В базе снято 1029 фальшивых пометок; `done` (37) и `failed` (22) не тронуты
- `DEFAULT 'pending'` с колонки снят

## 2. Скорость

### Клик перестал перезагружать всю страницу

- Каждый элемент строки после запроса просил сервер собрать список заново:
  **879 мс** на 222 встречи, 553 мс на 383
- Ждать было нечего — звезда и тип показываются из состояния самого элемента
- Обновление нужно только числам по всему списку, им можно отстать
- Пять кликов → одно обращение вместо пяти

### Одна разметка вместо двух

- В документ уходили и строки таблицы, и карточки для узкого экрана; одна
  копия всегда пряталась
- **1110 кнопок-звёзд**, нарисованных чтобы быть скрытыми
- Теперь строка сама складывается на узком экране

### Поиск готов к индексу

- Сейчас: подстрока по расшифровкам, индексом не ускоряется —
  2647 / 1617 / 1284 мс
- Готово: колонка со словами + GIN-индекс, разбор `simple` (встречи на трёх
  языках, любой «язык разбора» испортил бы два из трёх)
- Поиск по половине слова сохранён вручную: «fath» находит «fathom»
- Код не ждёт миграции: пробует индекс, не находит — работает по-старому
- **Ждёт одной команды в Supabase**

## 3. Работать удобнее

- Строка таблицы 117 → **61 точка**; верх таблицы 150 → 92; на экран влезает
  вдвое больше встреч
- Кликается вся строка, а не только текст названия (на телефоне так было
  всегда, на компьютере — нет)
- Клавиатура: `/` — поиск, `j`/`k` и стрелки — по списку, `Enter` — открыть,
  `Escape` — сбросить, `g`/`G` — к краям
- Ни одна клавиша не срабатывает, пока человек печатает
- Во вкладке браузера — маскот вместо стандартной иконки Next.js

## 4. Надёжность

### Проверки на входе (13 маршрутов API)

- Размер тела: потолок 64 КБ — раньше пятьдесят мегабайт разбирались в память
  целиком
- Битый JSON → 400, а не 500
- Кривой идентификатор ловится до базы
- Поля приведены к общим разборщикам

### Лимиты запросов

- Правка 60/мин, ключ Fathom 10/мин, синхронизация 5 за 10 мин,
  коннектор 120/мин, подбор секрета 20/мин
- Честно: счётчики в памяти одного экземпляра, а их несколько — это защита от
  сорвавшегося скрипта, не от распределённого потока

### Тесты

- Было **ноль** → стало **179 проверок в 9 файлах**, команда `npm test`
- Базы и переменных окружения не требуют, идут за секунду
- Фреймворка нет намеренно: зависимость, которую надо ставить, перестают
  запускать
- Линт: было 5 ошибок «состояние из эффекта» → 0

## 5. Что нашли по дороге

_Ошибки, которых не искали — их вскрыли тесты и замеры._

- **Группировка брала только первое значение строки.** Встреча с двумя типами
  показывалась под первым; при группировке по людям — только у первого
  участника, у остальных исчезала. В общем компоненте таблицы это чинили
  раньше, у дашборда своя группировка — там осталось
- **Мёртвый код:** строка рисует конспект под названием, но поля конспекта в
  списочном запросе не запрашиваются — эта подпись не показывалась никогда
- **Ячейка даты не была флекс-контейнером** — на глаз выглядело бы «строка
  немного высоковата», поймано измерением раскладки

---

## 6. Решения, которые стоит помнить

- **Сырые данные не трогаем.** Строки участников хранят то, что сказал
  Fathom; склейка происходит по дороге на экран
- **Разбор `simple` для поиска.** У нас три языка сразу — выбрать один разбор
  значит испортить два
- **Об ограничениях говорим прямо.** Лимит в памяти экземпляра описан в самом
  модуле: защита, которой доверяют больше, чем она может, хуже её отсутствия
- **Чистые правила выносим** из React и из базы — тогда их можно проверить без
  браузера и без подключения (`lib/keys.js`, `lib/coalesce.js`,
  `lib/search-query.js`, `lib/column-types.js`)
- **Тест пишем до правки.** Три раза оказалось, что права не я, а код —
  ожидания переписаны под настоящее правило, а не наоборот
