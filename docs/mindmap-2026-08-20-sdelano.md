# Fathom Database — что сделано, 20 августа 2026

Заметки для майнд-карты. Разложены **логически**, а не по времени: ветки — это
части продукта, а не часы дня. Цифры измерены на живой базе в тот же день.

Рядом лежит `mindmap-2026-08-20.md` — заметки того же дня со стороны аудита,
про долги и находки. Здесь — про сделанное.

---

## 1. Витрина: список встреч

- **Таблица стала таблицей**
  - плотность строк 61px, разделители между колонками, цифры одной ширины
  - первая колонка (дата) примерзает при прокрутке вбок; при группировке
    выключается
  - чередование фона через строку — полоса задаётся переменной, а не заливкой,
    иначе перебила бы наведение, жёлтую строку «нужно имя» и курсор
  - ширина колонок тянется мышью и стрелками, запоминается в браузере; первое
    движение замораживает все дорожки в пикселях
- **Сводка слева**
  - крупное число, четыре показателя сеткой, типы с полосами
  - длина полосы считается от самого частого настоящего типа; «без типа»
    полосы не получает — это пробел в данных, а не тип
  - цена решения: блок вырос с 94 до 254 пикселей
- **Отбор по датам** (новое)
  - два поля с календарём браузера плюс четыре быстрые кнопки
  - живёт в адресе (`?from=&to=`) — ссылкой можно поделиться
  - отбор по киевскому дню, не по UTC: встреча в 00:30 по Киеву иначе выпала бы
    молча
  - обе границы включительно; перепутанные концы меняются местами
- **Выгрузка в файл** (новое)
  - CSV и Markdown; уезжает ровно то, что на экране, и в том же порядке
  - экранирование по RFC 4180 плюс метка UTF-8 (без неё Excel даёт кракозябры)
  - промежуток дат в имени файла
- **Пакетные действия** (новое, самое крупное)
  - галочки в строках, трёхсостоянийная в шапке; берётся то, что прошло
    фильтры, а не вся база
  - отметка не красит фон: галочка, планка на внутреннем крае ячейки,
    акцентные линейки сверху — фон уже занят тремя состояниями
  - клавиатура: `x`, `Shift+X`, `a`, `Esc`
  - панель внизу: задать тип, задать важность, снять, «Отменить» одним
    сгруппированным запросом
  - «изменено 9 из 12» считает сервер — только он знает нынешние значения;
    ссылка «показать их» открывает те три, что не изменились

## 2. Честность данных

- один человек под разными никами больше не двоится в списке (union-find плюс
  транслитерация); три пары машина свести не может — нужен ответ человека
- фальшивая очередь «в разборе» убрана: `pending` больше не выдаётся за работу
- пакетная правка видна в строках сразу — ячейки принимают серверное значение,
  а не держатся за своё (ошибка, найденная в живой работе)

## 3. Надёжность

- **374 проверки в 18 файлах**, запуск на каждый пуш (GitHub Actions, ~40 сек)
- сторожа за тем, что ломается молча:
  - контраст 4.5:1 для каждого цвета текста на каждой поверхности
  - правило внутри `@media` не может быть слабее того, что отменяет
  - отметка строки не имеет права красить фон
  - в каждой строке Markdown ровно столько разделителей, сколько колонок
- **журнал синхронизаций**: строка на каждый запуск, открывается до работы и
  закрывается после — незакрытая строка и есть след аварии; настройки говорят
  словами одно из пяти состояний
- чего проверки не ловят: живое приложение за входом через Google — два бага
  доехали до боя именно поэтому

## 4. Выкладка

- автоматической выкладки нет, деплой ручной с машины
- из-за этого 18–20 августа на бою месяц стояла старая сборка
- `npm run deploy` — тесты идут перед выкладкой
- автовыкладка упирается в одно действие владельца репозитория: доступ
  приложения Vercel к репозиторию; прав на запись для этого мало

## 5. Безопасность

- найдена дыра: `custom_columns` без RLS, публичный anon-ключ читал и писал её
- проверено этим ключом: 200 и чужая строка с `owner_email`
- политики не нужны — весь законный доступ идёт сервисным ключом
- `enable row level security` вписан в миграции, чтобы следующая база не
  повторила дыру; выполнить в Supabase остаётся человеку
