## 1. Дыра в доступе

### `custom_columns` без RLS

- Публичный anon-ключ лежит в браузерном бандле — его видит кто угодно
- Проверено этим ключом: `SELECT *` → **200**, вернулась строка с
  `owner_email = ceo@aivocado.ai`; `INSERT` → **201**, строка создана
- Пробная строка удалена сервисным ключом сразу же; в таблице снова ровно
  одна законная запись
- Остальные таблицы — `meetings`, `participants`, `fathom_accounts`,
  `sync_runs` — под RLS без политик, anon получает пустоту. Правильно
- Лечится одной строкой: `alter table custom_columns enable row level
  security;` — политики не нужны, весь легальный доступ идёт service-ключом
- Ту же строку положить в `db/custom-columns.sql`, иначе потеряется при
  следующем развёртывании

## 7. Скорость: что хорошо и что упрётся

### Поиск — сделано хорошо

- GIN-индекс живой, вчерашняя миграция применена
- Три прогона подряд: `gin` 333 → **164** → **165** мс против
  `ilike` 913 → 917 → 896 мс. Пятикратный выигрыш
- Но `searchMeetingIds` после индекса всё равно тянет **все** id встреч
  владельца и бьёт `participants` чанками по 300 — лишние круги поверх
  быстрого индекса

### Загрузить всё — потолок виден

- Каждая страница (`/`, `/people`, `/records` и даже карточка одной встречи
  `/meetings/[id]`) тянет **все** встречи владельца
- Фильтрация, сортировка, группировка — в Node, не в Postgres
- Замерено: `getMeetings(ceo)` 456 встреч — **1196 мс**;
  `getMeetings(d.soloviov)` 383 встречи — 561 мс
- На 456 терпимо. На 5000 страница перестанет открываться

### Объём

- Транскрипты: **44.8 МБ** на 1100 строк, средний 42 КБ, максимум 300 КБ
- Плюс GIN-индекс поверх `search_doc`, куда `raw_transcript` входит целиком
- **36 записей хранятся дважды** — одна встреча на каждого владельца, вместе
  с транскриптом. Это версия 1 по замыслу, но объём растёт линейно
- На бесплатном Supabase (500 МБ) запас пока есть

## 10. Оценка проекта: 7 из 10

**За что высоко.** Миграции идемпотентны. Комментарии объясняют «почему», а
не «что» — `sync-log.sql` с рассуждением, почему одного `last_synced_at` мало,
это уровень, который редко встречается. Замеры до и после индекса. Честная
оговорка про лимит в памяти экземпляра. Дедуп людей с транслитерацией. i18n на
три языка. Деплой через `npm test && vercel`.

**За что минус три.** Открытая дыра в доступе. Схема, которую нельзя
воспроизвести и в которой четыре названия у одной встречи. Модель людей,
живущая только в оперативной памяти. Архитектура «загрузить всё» с видимым
потолком. Два пайплайна — разбор и журнал синка — написаны, но не работают.

Это не прототип. Это рабочая система с живыми пользователями и накопленным
долгом.
