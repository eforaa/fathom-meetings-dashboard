# Перенос look + фич AI-researcher на Fathom

Дата: 2026-09-07
Статус: одобрен (дизайн), к реализации фазами

## Цель

Перетянуть визуальную «подпись» и ключевые фичи витрины **AI-researcher**
(`C:\Users\nehoc\ai-researcher`, Next.js + Supabase + `@aivocado/mindsheet`) на
дашборд встреч **Fathom** (`fathom-soritng`, тот же стек, но JSX).

Объём согласован с пользователем: look **и** все четыре фичи ниже.

## Принцип реализации

Нативная адаптация под модель встреч Fathom — паттерны AIR переосмысляются под
данные встреч (Supabase), файлы `.tsx` **не** копируются буквально (Fathom на
JSX, данные другие). Отклонённые альтернативы: общий пакет компонентов на оба
проекта (хрупко, проекты разошлись) и буквальное копирование файлов (не
заведётся).

Обе кодовые базы уже используют один набор CSS-токенов («editorial theme»),
одни шрифты (DM Sans + JetBrains Mono) и `@aivocado/mindsheet`, поэтому «look»
совпадает ~80% — переносится только недостающая часть.

## Решения пользователя

- **Сохранённые виды** хранятся в **localStorage** (ключ per-account), не в БД.
- **Корзина** реализуется как **«архив = корзина»** поверх существующего поля
  `meetings.archived` — отдельного `deleted_at` и миграций нет.

## Фазы

Порядок 1→4, каждая шиппится отдельно, по возрастанию риска.

### Фаза 1 — Look (только презентация)

- В `app/globals.css` добавить недостающие токены: `--gradient-header`
  (`linear-gradient(90deg, #4f7cff, #a87bff, #e85d9c)`), `--glass-hover`,
  `--glass-blur` (`saturate(180%) blur(14px)`), при необходимости `--radius`/
  `--radius-lg`. `--glass-bg` уже есть.
- Градиентная полоса в шапке: новый CSS-класс в `app/page.module.css`,
  применяется в шапке `app/page.jsx` (тонкая линия/бренд-блок).
- Стеклянная полировка всплывающих панелей и меню (column-manager, gaps-menu,
  preview-panel): правки только в их `.module.css`, разметка не меняется.
- **Изоляция:** чистый CSS, ни один компонент не переписывается.

### Фаза 2 — ⌘K глобальный поиск

- Новый клиентский компонент `app/command-palette.jsx` (+ `.module.css`):
  модалка по ⌘K / Ctrl+K поверх текущего `search-box`.
- Источники: встречи (переиспользуя серверный поиск `searchMeetingIds`) и
  быстрые действия (перейти в Люди/Настройки/Корзина, сменить тему/язык).
- Монтируется в `app/layout.js` рядом с `Shortcuts`; хоткей регистрируется по
  образцу существующего `app/shortcuts.jsx`.

### Фаза 3 — Сохранённые виды + карточки

- **Виды:** `app/saved-views.jsx` — сохранить текущий URL-вид (фильтры +
  группировка + сортировка, читаемые через `lib/tags.js#readView`) под именем
  в localStorage; список видов; применение = навигация на сохранённый URL.
  Ключ хранилища привязан к аккаунту.
- **Карточки:** переключатель «таблица ⇄ карточки» в тулбаре; новый
  `app/cards-view.jsx` рендерит те же встречи карточками. Режим — в URL
  (`?view=cards`), чтобы шарился ссылкой, как остальное состояние.

### Фаза 4 — Корзина + конструктор фильтров

- **Корзина:** страница `app/bin/page.jsx` — список встреч `archived = true` и
  «Восстановить» (переиспользуя существующий bulk `archived:false` из
  `lib/bulk.js`). Пункт в навигации. Без миграций.
- **Фильтры по условиям:** порт `filter-conditions` из AIR в JSX —
  `app/filter-conditions.jsx` + `lib/filter-conditions.js` (модель И/ИЛИ,
  кодирование в URL `?cond=`), поверх текущих колоночных фильтров
  (`lib/tags.js#applyColumnFilters`).

## Данные и совместимость

- Никаких схемных миграций.
- Состояние вида остаётся в URL (кроме именованных сохранённых видов) —
  шаринг ссылками сохраняется.
- i18n: новые строки в `lib/i18n/ru.js` и `lib/i18n/en.js` (проект двуязычный).

## Тестирование

- `npm test` (`tests/run.mjs`, включая `tests/contrast.mjs`) после каждой фазы;
  новые цветовые токены обязаны пройти контраст.
- Ручная проверка в браузерном preview после каждой фазы, скриншоты
  пользователю.
