## 1. Включить журнал синхронизаций · 10 минут

**Зачем.** Сбор встреч работает по расписанию, раз в сутки. Сейчас на бою есть
страница, которая должна показывать «сбор идёт по расписанию» или «сбор стоит
третий день», но она пустая: таблицы, куда пишется история, в базе ещё нет.
Пока её нет, молча остановившийся сбор так и останется незаметным.

**Как.**

1. Открой [supabase.com](https://supabase.com), войди, выбери проект Fathom.
2. Слева в меню — **SQL Editor**, вверху кнопка **New query**.
3. Вставь текст ниже целиком и нажми **Run** (или Ctrl+Enter).

```sql
create table if not exists sync_runs (
  id uuid primary key default gen_random_uuid(),
  user_email text not null,
  source text not null check (source in ('cron', 'manual', 'backfill')),
  started_at timestamptz not null default now(),
  finished_at timestamptz,
  ok boolean,
  error text,
  fetched integer,
  inserted integer,
  skipped integer,
  people_refreshed integer,
  meetings_total integer
);

create index if not exists sync_runs_email_started_idx
  on sync_runs (user_email, started_at desc);
```

Должно ответить `Success. No rows returned`. Запускать повторно безопасно.

**Как убедиться, что получилось.** Открой в приложении **Настройки**, нажми
**Синхронизировать**, подожди несколько секунд и обнови страницу. Внизу, в
разделе «Сбор встреч», должна появиться первая строка истории: когда, кем
запущен, итог, сколько новых встреч.

## 2. Ускорить поиск · 10 минут

**Зачем.** Поиск сейчас читает подряд все расшифровки всех встреч. Замерено на
твоей базе: «клиент» — 2805 мс, «архитектура» — 1520 мс, «fathom» — 1204 мс.
Это секунды ожидания на каждый запрос, и дальше будет хуже: расшифровок
становится больше каждый день.

**Как.** Тот же SQL Editor, новый запрос, вставить и запустить:

```sql
alter table meetings
  add column if not exists search_doc tsvector
  generated always as (
    to_tsvector(
      'simple',
      coalesce(title, '') || ' ' ||
      coalesce(ai_title, '') || ' ' ||
      coalesce(custom_title, '') || ' ' ||
      coalesce(fathom_title, '') || ' ' ||
      coalesce(summary, '') || ' ' ||
      coalesce(custom_summary, '') || ' ' ||
      coalesce(fathom_summary, '') || ' ' ||
      coalesce(raw_transcript, '')
    )
  ) stored;

create index if not exists meetings_search_doc_idx
  on meetings using gin (search_doc);

create extension if not exists pg_trgm;

create index if not exists participants_name_trgm_idx
  on participants using gin (name gin_trgm_ops);

create index if not exists participants_email_trgm_idx
  on participants using gin (email gin_trgm_ops);
```

Этот запрос думает дольше — он один раз перечитывает все расшифровки, чтобы
построить индекс. Минута-другая на такой базе — нормально.

**Важно:** приложение переключится само. В коде уже написано «попробуй индекс,
а если его нет — ищи по-старому». Ничего выкладывать не нужно.

**Как убедиться.** Поищи в приложении что-нибудь и скажи мне — я замерю то же
самое и покажу, сколько было и сколько стало.

## 3. Попросить владельца репозитория про автовыкладку · 2 минуты

**Зачем.** Сейчас код попадает к людям только когда кто-то вручную наберёт
`npm run deploy`. Забыть это — вопрос времени: с 18 по 20 августа на бою месяц
стояла старая версия именно поэтому.

Подключить репозиторий к Vercel может только его владелец: у тебя доступ на
запись, а нужен админский. Перешли ему это:

> Привет! Подключаю автоматическую выкладку дашборда встреч на Vercel, но
> упираюсь в права: репозиторий `eforaa/fathom-meetings-dashboard` твой, а у
> меня доступ на запись, без админских.
>
> Нужно одно действие с твоей стороны: зайти на
> github.com/settings/installations, открыть приложение **Vercel** и дать ему
> доступ к репозиторию `fathom-meetings-dashboard`. Либо выдай мне права
> администратора на этот репозиторий — тогда я подключу сама.
>
> После этого каждый пуш в `dev` будет уезжать на боевой адрес сам, а не
> ждать, пока кто-нибудь вспомнит выложить руками.

## 4. Посмотреть на приложение своими глазами · 10 минут

**Это единственная проверка, которой у нас нет, и подменить её нечем.** Всё
сделанное проверено тестами и измерено, но приложение закрыто входом через
Google, и я его не видела ни разу. Я знаю, что всё устроено правильно. Я не
знаю, удобно ли этим пользоваться.

Открой [fathom-soritng.vercel.app](https://fathom-soritng.vercel.app) и просто
поработай минут десять. По дороге посмотри на пять новых вещей:

1. **Ширина колонок.** Наведи мышь на стык двух заголовков — появится
   вертикальная линия. Потяни. Двойной щелчок по стыку вернёт одной колонке
   исходную ширину, кнопка над таблицей — всем сразу.
2. **Дата не уезжает.** Прокрути таблицу вбок: первый столбец должен остаться
   на месте, остальные — уехать под него.
3. **Полосы.** Каждая вторая строка чуть темнее. Вопрос к тебе: помогает вести
   взгляд или мельтешит?
4. **Клавиатура.** Нажми `j` и `k` или стрелки — по списку должен ходить
   курсор. `Enter` открывает встречу, `/` открывает поиск, `Esc` убирает
   курсор.
5. **Сводка слева.** Крупное число, четыре показателя, типы с полосами. Она
   стала выше почти на 160 точек — не давит ли.

**Что мне сказать.** Не «плохо выглядит», а что именно мешает: «полосы
рябят», «сводка занимает пол-экрана», «не могу попасть в стык мышью». Из
такого я делаю правку, из «не нравится» — нет.

## Если останется время

`tests/dates.mjs` — упражнение, которое ты просила: два примера показаны,
шесть заданий ждут. Запускается одной строкой в папке проекта:

```bash
node tests/dates.mjs
```

Правило там одно: сначала напиши, что ДОЛЖНО получиться, и только потом
запускай. Если не сошлось — сначала подумай, кто не прав: тест или код. Оба
варианта бывают, и за эти два дня у меня было и то, и другое.
