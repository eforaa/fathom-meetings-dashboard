# Таблица встреч

Ты работаешь с базой встреч как с таблицей Excel: показываешь строки,
фильтруешь и правишь ячейки. Всё идёт через подключённый коннектор
**fathom-meetings**. Ты видишь и меняешь **только встречи владельца токена** —
чужие тебе недоступны.

Если задача — сделать разбор встречи (заголовок, темы, тип, задачи из
транскрипта), это отдельный скилл `analyze-meeting`. Здесь — только табличная
правка того, что уже есть.

## Колонки таблицы

| Ячейка | Чем читать | Чем править | Значения |
|---|---|---|---|
| Название | `list_meetings` / `get_meeting` | `set_meeting_title` | текст до 120 символов; пустая строка вернёт авто-название |
| Саммари | `get_meeting` | `set_meeting_summary` | текст; пустая строка вернёт машинное саммари |
| Важность | `list_meetings` / `get_meeting` (`importance`) | `set_meeting_importance` | 0–5, где 0 очищает |
| Типы | `list_meetings` / `get_meeting` (`types`) | `set_meeting_types` | массив, до 4 значений из списка ниже |
| Своя колонка | `list_meetings` / `get_meeting` (`custom_fields`) | `set_meeting_field` | по типу колонки; нужен `column_id` |

**Типы встречи** — ровно из этого набора:
`internal_planning`, `client_meeting`, `automation`, `onboarding`, `other`.

**Типы колонок**: `text`, `number`, `select` (один вариант из списка),
`multiselect` (несколько тегов в одну ячейку, из списка), `checkbox`.

## Показать встречи

1. `list_meetings` — строки таблицы. Фильтры: `type`, `search` (по названию),
   `participant` (имя/почта), `date_from`, `date_to`, `limit`, `offset`,
   `needs`.
   **`needs` — про пробелы:** `summary` (нет конспекта), `type` (нет типа),
   `rating` (нет оценки). Те же три фильтра, что кнопками в таблице. Ими же
   берут очередь на разбор — но сам разбор это скилл `analyze-meeting`.
   В ответе уже есть важность, типы и значения своих колонок.
   **Все встречи человека:** один человек бывает под несколькими алиасами (разные
   имя/почта, кириллица/латиница). Поиск по одному email пропустит часть. Сначала
   `search_participants` по фамилии/имени/почте → все алиасы, затем собери встречи
   по каждому и объедини по `id`.
2. `list_custom_columns` — какие пользовательские колонки существуют и их `id`.
   Вызывай **до** правки ячеек своих колонок — `column_id` берётся отсюда.
3. `get_meeting` — одна встреча целиком плюс участники.
4. `get_stats` — сводка: сколько встреч, по типам, по статусам.

Показывай результат человеку как таблицу (Markdown), а не сырой JSON.

## Править ячейки

- **Название**: `set_meeting_title` (`id`, `title`).
- **Саммари**: `set_meeting_summary` (`id`, `summary`).
- **Важность**: `set_meeting_importance` (`id`, `importance` 0–5).
- **Типы**: `set_meeting_types` (`id`, `types` — массив). Неизвестные значения
  отбрасываются, лишние сверх 4 обрезаются, пустой массив очищает типы.
- **Своя колонка**: `set_meeting_field` (`id`, `column_id`, `value`). Для
  `select` значение — один из вариантов колонки. Для `multiselect` — **массив**
  вариантов (несколько тегов в одну ячейку). Неверные значения отбрасываются.
  Пустое значение (или пустой массив) очищает ячейку.

## Раскладывать по папкам

Папка — это не ячейка встречи, а **дерево**, которое человек складывает руками:
проект, клиент, направление, внутри — подпапки. Колонка `select` так не умеет:
у проекта бывают подпроекты.

- **Посмотреть**: `list_groups` — всё дерево. У строки есть `id`, `name`,
  `parent_id`, `depth`, `path` (полный путь — по одному имени подпапку не
  узнать) и **два счётчика**: `meetings_here` (лежит ровно здесь) и
  `meetings_total` (вместе с подпапками). Не путай их.
- **Что в папке**: `list_group_meetings` (`group_id`). По умолчанию отвечает
  вместе с подпапками — так же, как показывает экран; `include_descendants:
  false` даёт ровно эту папку.
- **Завести**: `create_group` (`name`, для подпапки — `parent_id`).
- **Переименовать / перенести**: `rename_group`, `move_group`
  (`parent_id: null` поднимает в корень). Перенести папку внутрь себя или своей
  подпапки нельзя — откажут, и это не ошибка вызова, а правило.
- **Разложить**: `assign_meetings_to_group` (`group_id`, `meeting_ids`, до 200).
  **Добавляет, а не переносит:** встреча может лежать в нескольких папках
  сразу, и один созвон честно бывает и «Клиент Acme», и «Найм». Чтобы
  именно переместить — добавь в новую и убери из старой. Повторное добавление
  не задваивает. Пачка сверх 200 отклоняется целиком, а не обрезается.
- **Убрать**: `remove_meetings_from_group`. **Встречу это не удаляет** — она
  выходит из этой папки и остаётся везде ещё.
- **Удалить папку**: `delete_group`. **Встречи остаются.** По умолчанию
  подпапки поднимаются на место удалённой; `cascade: true` удаляет ветку
  целиком (встречи и тогда целы). Перед удалением непустой папки спроси.

Раскладывая архив: сначала покажи предполагаемое дерево и 3–5 примеров
«встреча → папка», дождись «ок», и только потом проходи остальное пачками.

## Управлять колонками

- **Создать**: `create_column` (`name`, `type`, для `select` — `options` списком).
- **Удалить**: `delete_column` (`column_id` из `list_custom_columns`). Удаление
  убирает колонку из таблицы; значения, уже проставленные на встречах,
  физически остаются, но больше не показываются. Предупреди об этом.

## Правила

- **Перед массовой правкой** (несколько встреч за раз) сначала покажи список
  того, что собираешься изменить, и дождись подтверждения. Одну ячейку правь
  сразу.
- **id встреч и колонок** бери только из инструментов, не придумывай.
- **Значения из списков** соблюдай строго: типы — из пяти разрешённых, значение
  `select`-колонки — из её `options`.
- **Не создавай встречи** — они приходят из Fathom, ручного добавления нет.
- После правки коротко подтверди, что именно изменил, без пересказа всей строки.
